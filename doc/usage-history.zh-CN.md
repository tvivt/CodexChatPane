## 入口与显示

状态栏额度可点击或用 Enter/空格打开独立的 `usage-history` 窗口。默认显示“重置记录”，当前 W 周期置顶并展示最近 5 次已结束周期。切到“消耗详情”时默认选择当前 W 周期；仅有历史 W 时选择最近周期，没有 W 记录时使用当前自然月。启动和首次额度查询不自动索引当前周期；消费只由打开的消耗范围、可见/展开的重置行或实际通知触发。

消耗详情按“范围栏 → 横向筛选 → 概览 → 趋势 → 汇总表”排列。“重置周期”和“自然时间”互斥，各自保留选择，不取交集。重置周期仅统计 W，下拉框复用重置记录已加载的周期，每行显示起止时间和周期长度，当前周期显示已持续时长，不显示重置方式；点击周期文字立即单选，勾选框可选择当前周期或不连续的多个历史周期，点击“应用”后按并集加载。显式选择“所有周期”会逐月补齐更早的本机历史边界，再按全部已记录 W 周期的并集计算，不受当前显示的 5 条限制；缺少边界的历史不推造周期。周期起点显示年份，终点不重复年份；周期显示、时长与统计查询统一采用同一事件边界，前后观察时间仅供诊断。自然时间用日/周/月/全部按钮，配合日期及前后切换；日以本地零点、周以周一零点、月以每月一日为界。自然时间“全部”不限制历史时间。

项目、来源（全部/主对话/子代理）与 Fast 用横向按钮切换，同类单选、跨类组合。模型作为消耗拆分，不再提供模型筛选和独立“按模型”按钮。顶部使用同一张表显示总计及模型总体行，列为模型、API 等价金额、输入/输出、缓存命中率及请求数；总计另外保留对话数。默认显示金额最高的 5 个模型，其他模型可展开，总计始终包含全部。缓存率为所有缓存输入之和除以所有输入之和，不平均模型百分比。推理、缓存输入和主/子代理金额与 Token 构成放在 tips，避免堆高每一行。

趋势右上角直接切换“Token / API 等价金额”，默认 Token。每个本地自然日一根堆叠柱，不合并成跨日分桶；模型按固定名称顺序堆叠，同一模型颜色由名称确定，与日期、模式和大小无关。Token 为 input+output，缓存包含在 input、推理包含在 output，不再相加。API 金额只堆叠已计价部分，未计价请求保留 Token、提示金额不完整并显示斜纹标记，不能当作零美元。日期标签按宽度减少，长范围柱体压缩到窗口宽度，不依赖横向滚动。tips 显示日期、当天合计及各模型金额/占比、Token/占比、输入输出、推理、缓存输入/命中率、请求和主/子代理构成。切换模式只重绘当前报告，不读取日志；子代理按实际模型计入相应色块。

默认按项目、按金额倒序，可按列排序或用按钮切换“按项目 / 按对话 / 按日期”。项目和日期行默认显示合计，点击后展开模型子行；模型子行缩进并使用统一颜色，沿用请求、输入、缓存率、输出和金额等列。子行只是父合计的拆分，不再次相加。按对话的顶层使用主对话标题，金额包含自身和全部所属子代理。点击标题后有“模型构成”展开项、“本对话轮次（仅主对话自身）”及“子代理明细”。模型构成直接复用当前报告。轮次按时间倒序显示首次提问摘要、起止时间、状态和筛选内用量，不把同一轮按模型拆成不同父节点；子代理列出名称、实际模型及消耗，点击名称打开独立对话详情。子代理再创建子代理时，各自在明细中只计算自身请求，不把已汇总子项再次相加。尚未定位父对话的代理保留其消耗并标注“所属对话未定位”，不丢弃、不猜测归属。两页表格均使用内容驱动列宽、压缩单元格间距，标题换行，数字保持完整；只有内容确实放不下时才水平滚动。

每轮从用户首次提问开始，到最终回复结束；同一技术 turn 内插话、补充要求和工具调用不分轮。请求校验与技术 turn 归属复用对话详情的 `metrics::read_own`，包括经过连续快照校验的旧 `token_count`；不改变已有详情解析。用户问答映射只负责消息摘要和续接：结构化 parent/root 关联及 `goal` 自动续跑沿用已有提问；中断后的明确“继续 / 接着 / continue / resume”指令沿用中断提问。新的独立 turn 不仅凭上一轮未完成就合并；没有明确续接依据时保留独立提问。`task_complete` 或明确 final 作为结束边界，重复和已中断 turn 的迟到结束事件不覆盖续接状态。内部上下文消息不冒充用户提问。缺少可靠消息关联的已结算请求保留在“轮次未识别”，不丢失、不猜造归属。

轮次沿用当前周期/自然时间、项目、来源与 Fast 筛选，只累加当前主对话自身在范围内的已结算请求；跨边界标“部分消耗”，不把范围外用量带入。范围内确有提问但没有可靠已结算用量时仍显示该轮并标“用量未记录”，不显示成零。普通分组不解析所有对话消息，只有展开目标对话才补读该对话的边界及所需历史段。只筛选子代理时不读取主对话轮次；只筛选主对话时不加载代理明细。子代理不按时间猜分到父轮。主轮合计加“轮次未识别”须与同范围主对话消耗一致，子代理另行对账。输入是所有模型请求的实际输入之和，包含重复上下文，不是用户问题文本的 token 数；推理已包含在输出内，不能再相加。既有“对话详情”仍显示全部自身已结算用量和技术轮次，独立于速度计时范围。可靠用量即使缺少速度计时也可计价；进行中和中断轮次的已结算请求纳入，继承历史、其他 thread_id、重复和冲突请求排除。未计价的用量保留，不显示为免费。

“重置记录”Tab 位于“消耗详情”之前。当前周期独立置顶，默认展示最近 5 次已结束周期，“加载更多”每次追加 10 条；追加保留表格滚动和详情展开状态。已结束周期仅显示一行“2026年 10-25 14:11 - 10-26 13:58 (0d23h)”，当前周期显示“2026年 10-26 13:59 进行中 (0d5h)”（时长随读取时刻计算）。打开窗口先显示本地缓存的周期基本信息，后台检查新日志并补足边界。总 Token 复用已读取周期结果；进入重置记录后按可见行串行读取，滚动到其他历史周期再加载，不需要先展开详情，也不提前请求模型明细。等待时显示“…”；读取失败显示“—”并保留错误提示，不显示成零。真实重置起点缺失时，时长从页面显示的首次观测时间计算，悬停注明口径。展开才读取各模型总 Token、占比、输入、缓存占比、输出、其中推理、请求数和 API 等价金额，并保留周期覆盖、原定重置、耗尽时间和已观察消耗。顶部显示重置卡数量，展开显示到期时间，复用最近一次额度快照。

额度 tips 显示 `rateLimitResetCredits.availableCount` 和明细到期时间，按到期时间排序。明细缺失时数量仍以服务端总数为准。到期时间格式为 `2026-10-30 00:00 (-6d5h)`，超过 24 小时使用天和整小时。

提前重置通知保留到手动关闭，关闭状态持久化。同一事件不会在重启后反复通知。重置记录区分自然重置、重置卡、提前重置，不显示“推测”“已确认”“来源未知”后缀。通知第一行是“额度提前重置 MM-DD HH:mm 剩余百分比 ×”；第二行紧接“上次重置 MM-DD HH:mm 重置周期 XdXh”。采用与周期查询一致的事件边界，不另显示前后采样区间，不带年份或 W。下面自动展开各模型及合计，顺序为总 Token、Token 占比、API 等价金额，次行显示输入、缓存占比、输出、推理；明细略缩进，合计不重复显示 100% 占比。加载中的用量显示“…”而非虚构零。

## 额度周期

`usage/ledger.rs` 接收既有 MCP / CLI 回退的只读额度查询；`ledger/recognizer.rs` 统一识别，不兑换卡片，也不启动 Token 扫描。额度窗口是当前 `used_percent/window_minutes/resets_at`，重置事件保存一次变化的证据和稳定身份，消耗周期是相邻事件的统计区间。W/5h 独立；消费界面仍只按 W 分期，不能把两种窗口相加或等同订阅计费周期。账号切换、套餐变化分别记为独立边界。

### 窗口模式与候选

未知账号历史不能成为已知账号的判断基线：进入明确账号时重建窗口观察基线，缺账号的历史只留原始缓存及覆盖提示，不回写或猜测归属。仅来源标识缺失也不能当成“旧快照”的证据。截止时间候选不等于冻结整个窗口：后续一致观察可继续更新窗口和已观察用量，候选本身仍不创建重置；否则可能漏掉后续真实恢复。

- 单次观察的模式未知。两次相隔至少一秒且 deadline 差不超过 5 秒的观察可确认固定模式。浮动模式需要连续两段、至少三次观察；每段至少 10 秒，deadline 平移量与观察时间差相差不超过 5 秒，且各次 `deadline-observedAt` 距完整窗口不超过 5 秒。5 秒来自服务端秒级时间和真实回放至多约 3.3 秒的观察偏差，未用放宽原 60 秒门槛代替模式判断。真实 59/61/65 秒的滑动按时间几何关系识别，0% 不是模式条件。
- 已确认浮动窗口固定到某一 deadline，包括首次消费后的固定，只更新窗口，不移动已识别周期起点。数小时或数天未用也不以首次用量另建周期。若所有可观察字段仍与浮动模式相同，无法识别第二次未使用重置。
- 自然重置需要此前已确认的固定 deadline 到达，且新观察确实更新窗口；仅本地时钟越过时间、仍收到旧窗口不创建事件。
- 同一卡 `available → consumed/redeemed` 是独立证据。只减少数量、过期或卡列表暂缺不是兑换。结合发生更新的窗口或明确额度恢复归属，不受必须先有消耗或 60 秒门槛限制；多个窗口归属不明时保留诊断，不将卡事件复制到所有窗口。
- 提前重置要求额度恢复至少 1 个百分点并伴随窗口更新，再由后续一致观察确认未撤销。重新消费到原百分比或更高时，快照本身不能证明采样间的重置，保留候选；不恢复“上次有消耗就算重置”的规则。
- 仅 deadline 跳变、持续新 deadline、缺字段或来源冲突均不足以宣告重置。候选和原有效状态分开保存；回到正常窗口可撤销短暂异常。已见旧状态的交错副本保留诊断，不能将所有更早 deadline 一律丢弃。已标识在线 MCP、CLI、历史日志的冲突按来源和后续证据处理，连续一致的 CLI 回退可确认此前 MCP 窗口后的变化；旧来源缺失仍为未知。

### 采用边界与事件身份

事件保留变化前最后有效观察、变化后首次观察与采用边界。当前接口没有可靠的重置发生时间字段；自然重置采用原固定 deadline，快照识别的提前/卡重置采用变化前最后一次观察，账号/套餐边界采用新分区首次观察。显示、周期时长、筛选、Token 和金额全部使用 `startedAt/endedAt` 的同一半开区间 `[start,end)`；`boundaryFrom/boundaryTo` 仅保留诊断证据，不另作显示或查询边界。超过两分钟的宽观察区间标记不完整；不插值、不补造离线期间遗漏周期。首个周期 `startedAt` 仍未知，页面可从首次观察显示已观测范围，不能称完整周期。

事件以窗口及观察锚点关联，历史补证据后保留已有稳定 ID，不按 deadline 接近程度合并。存在多个旧锚点的歧义时不自动合并。W 保留原事件 ID（本次真实回放为 445），新 5h 事件 ID 带窗口后缀。旧滑动误通知只在同一已证明浮动的事件区间内建立别名；原始快照和 `quota_ack` 不删除。关闭按稳定 ID 或已验证别名持久化，重读/重启/历史细化不复活；历史补出的旧事件只入历史、不补弹通知。不按 0 Token、100% 剩余或周期短过滤通知。重置前余额取变化前有效观察，恢复后剩余不倒灌。

历史来自本机 `event_msg/token_count.payload.rate_limits`，W 可位于 primary 或 secondary。JSONL/ZST 按月补读复用已缓存的前后观察，不把月初当新周期起点。继承段按 session_meta/thread_id 排除，子代理的额度观察不是额外一份账户额度。明确其他账号不合并；未知账号、历史缺口与来源冲突保留不完整或待核对状态。日志不能覆盖云端、其他设备或服务端实际扣减时刻。已观察百分比消耗只累加正向变化，不能反推各对话额度。

## 消耗与计价

`usage/costs.rs` 复用 `metrics::read_own` → `metrics/analysis.rs`，同一次读取形成自己的逐请求用量、问答边界及紧凑额度观察，不保留完整正文。包含当前及中断轮次中已结算的请求；计时字段缺失不影响可靠 Token 统计。重复、冲突或非法用量不重复计入；继承历史按目标 thread_id 排除。

更早版本只有 `token_count.info.last_token_usage / total_token_usage` 时，使用 `metrics/legacy.rs` 校验逐次快照：本次累计输入、缓存和输出必须分别等于前次累计加本次用量；首个快照只接受累计等于本次用量的零基线。重复累计不重复计入；缺口、累计重置或继承切换后无法校验的请求跳过，后续连续记录继续校验。与新版逐请求记录在相邻结算时间且用量相同的快照去重。合成请求 ID 只用于稳定缓存，不补造速度计时；未识别原始轮次的用量保留在“轮次未识别”。格式版本 `usage-v3` 参与日志签名，旧解析结果在对应范围下次索引时更新，不强制扫描所有对话。

主对话与子代理费用分别累加，父子链归入同一主对话和项目，各请求仅统计一次。主对话轮次保持独立，不把子代理用量硬摊给父对话某一轮。概览对话数按主对话家族去重。以用量结算时间分日，跨天/跨周期对话按请求拆分；没有结算时间的请求保留在全部范围的“未分配”中，不按创建时间回填。项目归属使用当前主窗口目录映射；不是历史项目归属快照。已缓存的消费可在原始日志不可用时保留，读取错误在覆盖说明中显示。

API token 等价金额使用 `usage/pricing.rs` 的 USD/百万 token 价表，价表日期固定记录为 2026-10-23，来源为 <https://developers.openai.com/api/docs/pricing>。历史消耗按这一版公开 API 价格重新估值，不代表当时账单或订阅扣款。

- 分别计算未缓存输入、缓存读取和输出；推理已包含在输出内，不重复计费。
- Fast/priority 使用对应价格；长上下文按每次请求输入是否超过 272K 判定。
- 未记录档位时按 Standard 估算；缺少缓存写入量按普通输入，有写入量但没有 TTL 时按 30m 价格估算，并统计计价信息不完整的请求数。
- 模型或档位无匹配价格时显示未计价，不套其他模型价格；汇总只累加已知部分并提示未计价请求数。
- 本机自定义免计价规则：`gpt-reserve`、`codex-auto-review`、`gpt-5.3-codex-spark`、缺模型名称（含空名）的有效请求金额记为 0，不计入未计价请求。Token、请求数、主/子归属继续保留；此规则不是服务端免费承诺。其他未识别模型/档位仍保留未计价。报告缓存键追加 `local-zero-v1` 策略版本，旧报告按需从请求缓存重算，不重扫日志。
- 不包括工具调用、图片、音频等独立费用，也不将额度百分比换算为固定金额。

## 存储与性能

额度快照和关闭标记保存在 `CODEX_HOME/.codex-chat-pane/usage.sqlite`。消费明细和报告保存在同目录的 `usage-cache-<身份摘要>.sqlite`。`usage_log_analysis` / `usage_log_sources` 保存 `usage-analysis-v1` 的 parser、旧累计校验基线、去重/冲突、模型/档位、历史依赖与完整行偏移；普通 JSONL 追加只读新增完整记录及首行/游标前小块校验数据。`usage_round_details` 缓存请求与问答关联、轮次状态和首次提问前 160 字符；完整用户/工具/回复正文和登录令牌不持久化。一次必要的用量读取同时形成问答边界，展开才生成所需问题轮次报告；不为轮次或额度查询强制扫描全部 Token。

新在线观察的 `observation_source` 为 `online-mcp` 或 `cli-fallback`，历史合并标记 `history-log`；旧快照不补猜来源。`quota_derivations` 分账号、当前机器/数据源身份及 live/history 保存版本、紧凑输入前缀指纹、处理数量以及模式、候选、事件证据和卡核销证据；前缀未变从检查点继续，历史插入或输入修订只重放紧凑额度观察。`quota_event_alias` 保存已核实旧通知与保留事件的关联，关闭记录不改写。周期边界修订只丢弃受影响行的页面报告；相邻索引覆盖仍有效，按新范围从逐请求缓存重新分组，不清空全部范围或重扫全部 Token。

未变化的依赖复用检查点，不读源内容。物理路径、创建时间、长度、mtime、首行及游标前缀不符，截断、明文/压缩替换、history_base 链或解析版本改变时重建。半条尾行不推进安全偏移，不结算其中用量；旧格式累计基线、线程/轮次身份、重复冲突处理随检查点保留。大工具正文通过轻量类型投影跳过，必要记录才分配完整 JSON Value。相同扫描产出的额度观察可供历史合并复用，反向额度扫描不会启动全 Token 分析。常规追加校验不等于任意原地篡改的全文件哈希保证。首次分析可能略慢于旧解析，尤其持久化和轮次索引有额外成本；收益主要在不变/追加路径。

快照相同时合并观察时间。日常复用现有可见窗口每分钟额度查询，不为此增加全会话轮询。打开额度窗口先查询缓存，再检查当前月；已扫描范围不足以确定最近 5 次完整边界时才继续向前补月。“加载更多”每次追加 10 条，先使用已加载数据，不足时继续补月。一个月或一个文件没有覆盖所需边界时不能提前宣布完成。月边界内部使用 UTC，不影响页面本地时间显示。`get_quota_history(importLogs, before)` 仍执行单月导入，普通查询只合并缓存，不扫描日志。`quota_log_files` 保存各线程依赖签名、紧凑观察和读取错误，`quota_log_range` 保存历史下界，`quota_log_months` 保存确实扫描过的月份，使跨月停用后的中间空档仍会补查；旧缓存首次使用新覆盖标记时会按需重新检查月份，日志解析仍复用文件签名。JSONL/ZST、重命名压缩及 history_base 续接复用共享读取器。损坏或正在写入的替换日志不覆盖已恢复的观察，页面保留覆盖警告。

补读额度快照不同时索引全部历史 Token。消耗页首次按所选当前周期（无周期时当前自然月），重置表按可见周期串行加载 Token；其他范围按需索引。“所有周期”索引已记录周期并集，自然时间“全部”才是无时间限制全量。普通候选按目录创建/更新时间与范围交集筛选，已知变化 ID 绕过目录时间边界以避免漏结算，但只处理这些 ID。长对话/压缩文件首次仍可能顺序解码。打开、刷新和可见行共享同一身份/版本/范围下的在途任务，结束后不永久保留任务。关闭后停止下一条 UI 工作，已启动的共享后端任务正常完成，不取消其他消费者。已覆盖区间的分组/筛选只查缓存，另行保留变化 ID 的定向补索引；历史边界改变会使页面总量和范围提示失效。

选中对话仍使用当前轮次最新有效已结算请求的指标；Σ 则把运行中主对话各自至多 3 个同配置有效请求的加权预测相加，显示 `Σ≈125t/s`。工具执行及等待返回保留预测，无静默过期；有可靠证据的当前压缩排除。无参与项显示 `Σ0t/s`，有参与项但全无样本显示 `Σ—`，部分覆盖在 tips 标明。预测不写入消费金额/Token，不预测 TTFT，也不接入 OpenTelemetry。公式、配置隔离、增量资源及限制统一见[对话统计 4.5](conversation-metrics.zh-CN.md#45-σ-的近期请求预测2026-10-28)。

没有启动后的 3 秒全周期预加载。`usage-preload.js` 仅合并实际变化 ID：存在可见消费报告、可见/展开的重置行时才启动，等待 300 ms 合并并串行处理，后续变化保留下一批。分组/筛选/范围切换保留未处理 ID，已开始的旧视图结果不回填，必要时用同一批 ID 对当前查询重放；不退回无条件全范围索引。关闭/隐藏暂停未启动队列，恢复真实消费者后补处理；账号切换丢弃旧 ID 和旧结果。未出现在主目录的子代理、续接由文件监听传入。周期起点缺失使用首次观测，不猜测完整周期。

多选周期先合并相邻或重叠边界，每个未覆盖区间单独建立索引；不把最早到最晚之间的未选周期作为读取范围。最终汇总按区间并集过滤，每个请求只统计一次。已覆盖区间直接查本地缓存，快速筛选复用同一范围内正在进行的索引；账号切换清空范围提示和正在复用的任务引用，旧结果不能回到新账号页面。

状态栏和详情已解析的逐请求用量会直接合并到消耗明细，响应 ID 去重；部分读取不能把整份日志标记为已索引。完整索引只更新变化的请求及删除已不存在的请求。汇总按查询范围、分组、时区和价表日期持久化；按请求所在 UTC 日的修订号失效，无关日期的新消耗不会重算历史汇总。对话标题优先使用状态库中非空的 `threads.name`，缺失时回退 `threads.title`，与主列表一致。读取消耗报告时仅同步已索引对话的标题元数据，不重扫 Token 日志；名称变化会使旧报告失效。标题、项目归属、父子关系或覆盖错误变化时，汇总保守失效。损坏的汇总 JSON 会重算，原始日志变化时仍需检查和解析相应对话。

缓存身份包括 Windows MachineGuid、规范化 Codex 数据目录、状态数据库创建标识及服务端确认的账号 ID，解析版本参与键。换机器/来源/账号/状态库后使用独立缓存文件，原文件保留。每次启动先确认账号，不依据磁盘上次账号直接复用；账号未知、退出或 `auth.json` 变化时暂停消费缓存复用，直到重确认。精确对话统计仍可只读源文件，不强迫登录。账号切换清空详情筛选、变化队列与旧结果。报告为 `details-v7`、轮次为 `question-rounds-v2`，只按需重建，不清空逐请求或无关日期缓存。模型总体、每日模型堆叠和父行拆分在同一遍筛选中形成。

`usage_indexed_ranges` 只记录成功完成的非定向范围覆盖。`get_usage_consumption(refresh:false)` 返回缓存及 `indexed` 标记，缓存有数据先展示，再按需补索引；未索引、来源失败或半尾行不能认证成“已完整读取的 0”。分钟通知使用 `get_quota_history({liveOnly:true})`，只构建在线事件；历史页另按版本复用合并后的周期。周期缓存键含在线样本、导入修订、月覆盖、关闭标记和身份；同样快照的观察时间推进不重新解析所有导入观察。通知先展示可用缓存，再只补对应结束周期；轮询共用在途任务，关闭/账号切换后的结果不回填，失败不编造零金额。

日志未提供可靠的逐请求账号归属，切换账号不会把本机历史自动变成该账号账单；隔离的是缓存上下文，重新读取的仍是当前数据目录可见的本地日志。API 金额始终是本地会话估算。
