# v0.6.1

## 中文

- 动态栏普通对话到期自动移出，即使界面静置且没有日志事件，也会更新列表、项目分隔和状态计数。按最近有效到期时间调度一次刷新，复用内存数据；调整 Days、新活动、隐藏后恢复和休眠后延迟回调都会重新计算。
- 保留手动加入、手动移出及 0 Days 规则。拖动或调整栏位期间暂缓到期重绘，结束后补刷。
- 动态栏新增红色“出错”单选筛选，仅统计未读错误；黄色重试警告保留普通状态。错误与原四类状态互斥计数，仍受时间、手动规则、搜索和项目过滤约束。
- 排序统一为未读错误、待回答、待查看、工作中、已读，已读组按对话时间倒序。错误确认已读后不再置顶，保留当前标识和详情；解除或下一轮正常则清除，新错误重新待查看。同一错误的已读确认保存在本机，旧快照和重启不会反复置顶。
- “出错”位于 ALL 后第一个，警告图标缩小。状态图标和计数固定占位，避免数量变化造成位移；窗口拉伸后重新计算布局，大计数仍完整显示。
- 状态计数改为 10px 左对齐并贴近图标，收紧组内间距；ALL/已读预留三位，其余预留两位。联动图标保留动态栏原位置，仅一个工具被收纳时保留直接图标入口。
- 自定义项目顺序按稳定 ID 保存。暂时消失的项目回来时恢复原相对位置；新 ID 只有首次进入动态候选集才追加到末尾，项目目录不提前占位。搜索、状态/项目过滤与名称排序不改写自定义顺序，重启后继续保留。
- 兼容旧版排序：无法区分已存 ID 是真实历史还是目录预填，因此完整保留旧 ID 相对顺序，不猜测删除。旧预填 ID 仍可能保留原槽位，升级后的未记录 ID 按新规则追加。
- Windows 便携版通过 `v0.6.1` 标签触发 CI 构建并发布。
- 额度重置历史在详情前显示各周期的 API 等价金额，复用可见行的按需统计，首列收窄；自然重置方式去掉“待确认”，预计结束与预计周期仍保留标注。
- 主对话增量刷新同时索引所属子代理及下级子代理，避免新子代理消耗遗漏；已展开的子代理明细随刷新更新，时间筛选仍按请求发生时间计算。

## English

- Ordinary Activity chats expire automatically while idle, updating rows, project separators and status counts without log events. A single timer targets the next effective expiry using cached data. Days changes, new activity, visibility restoration and delayed callbacks after sleep recalculate the deadline.
- Manual inclusion, exclusion and zero Days retain their existing rules. Expiry redraws wait until an active drag or resize ends.
- A red Error status filter counts unread errors. Yellow retry warnings retain their ordinary state. Error counts are exclusive of the four ordinary states, with time, manual rules, search and project filtering still applied.
- Status order is unread errors, questions, unread, working and read; read chats sort by newest conversation time. Acknowledged errors stop taking priority while retaining their current icon/details. Recovery or a healthy next turn clears them; new errors become unread again. Local acknowledgement for the same error survives stale snapshots and restarts.
- Error follows ALL with a smaller warning icon. Fixed icon and count slots prevent status redistribution from shifting controls. Resizing recalculates layout while preserving full large counts.
- Status counts use compact 10px left-aligned text close to their icons. ALL/Read reserve three digits and other controls reserve two. Folder linkage stays in Activity; a sole overflow tool keeps its direct icon entry.
- Custom project order persists stable IDs. Returning projects regain their relative positions; an unrecorded ID appends only on its first entry into the Activity candidate set. Directory presence does not reserve a rank. Search, status/project filtering and name sorting do not rewrite custom order; restarting retains it.
- Legacy orders preserve every saved ID's relative position because actual past visits cannot be distinguished from old directory prefill. Legacy prefilled IDs can retain their prior slots; unrecorded IDs follow the new rule after upgrading.
- The `v0.6.1` tag triggers CI to build and publish the Windows portable executable.
- Reset history shows each cycle's API equivalent before Details using the existing lazy totals, with a narrower first column. Natural reset labels omit “unconfirmed” while estimated boundaries and durations remain explicit.
- Incremental parent updates also index descendant workers so newly created subagent usage is not missed. Expanded worker details refresh with the report; time filters still use request timestamps.
